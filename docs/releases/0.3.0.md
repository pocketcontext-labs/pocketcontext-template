TemplateContext 0.3.0 rebases the template onto the shared library [pocketcontext-core](https://github.com/pocketcontext-labs/pocketcontext-core) v0.1.3. The product stays a working hello-world `greetings` application on port 8098 in one binary with sync-safe database handling, and is still loopback-only.

- Project, working copy and write-back, lease, local routes, sign-in, UI development proxy, tunnel, database and sqliteuri come from pocketcontext-core, pinned to an exact tag. Everything product-specific is `internal/appconfig` (identity, policy, hooks, copy); the public route allowlist is explicit and empty. `internal/bundle` and `internal/tunnel` are gone.
- `tests/testdata/public_routes.json` freezes the anonymous route table generated from 0.2.1; `tests/public_routes.py` also pins foreign-Host refusal, loopback-only listening and the absence of any public listener option.
- `template.json`, `prompts/new-product.md` and `tests/identity_check.py` require a derived product to set every identity field, including its skill, profile registry, app id, port and executable. The check fails on any field left at the template's value.
- `build-tags.txt` is now copied from pocketcontext-core: the extra SQLite features earlier releases enabled (`dbstat`, `stat4`, column metadata, introspection, preupdate hook, unlock notify, virtual tables) are gone. A derived product that needs one adds it deliberately.
- `POST /api/bundle/password` is replaced by core's `POST /api/bundle/account`, which creates the one account or changes its password (with the local key). A second account is still refused by the hooks.
- A database from a different release is refused before PocketBase opens it, as before; the message comes from core and names the unknown migration.
