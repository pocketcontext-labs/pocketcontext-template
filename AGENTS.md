# TemplateContext

Template for local "*Context" applications built as one Go binary, with a hello-world data model (`greetings`). Read README.md and docs/data-model.md before changes; to turn the template into a new product, follow prompts/new-product.md.

- Keep the project to the database file, `storage/`, `templatecontext.json` and the binary. Everything machine-specific (working copy, logs, local key, unpacked assets, tokens, tunnel identity) belongs in the per-machine cache. Never write PocketBase runtime files (`.notify`, `auxiliary.db`, `types.d.ts`, backups) into the project folder.
- Never let the server open the synced database directly. Copy it in on start and write back only through consistent snapshots (`VACUUM INTO`) and atomic renames. Never overwrite a synced file that changed elsewhere; keep both and require an explicit `recover`.
- Do not add dependencies on external tools, Python or network services at run time. Hooks and migrations run in-process: no `$os.cmd`/`$os.exec` or other `$os` calls (`internal/bundle/hooks_test.go` enforces it; `sha256sum` and similar tools do not exist on every platform).
  The one exception is the opt-in `tunnel` command (`internal/tunnel`), which uses the tailcat library and its relays: it admits only the project's port, proxies it to `127.0.0.1` only, keeps its identity in the per-machine cache and never logs or echoes the address. Do not widen it (other ports, forwarding through the server, UDP, exit nodes, shells or files), and keep `build-tags.txt` in step with the tailcat release in `go.mod`.
- Keep authentication on: loopback only, Host check, own-origin CORS, ordinary `users` tokens. The local key never leaves the private cache. Records are private to their owner: the server sets ownership in hooks, collection rules and `server.json` snapshot filters restrict every read to the requester, and search indexes use `"isolation": "private"`.
- Remote mode (`--url`) is a client only: it never resolves or creates a database, never starts a server and never reads the local key. It accepts loopback URLs only and stores a token, never a password.
- The SQL reader exposes only the columns listed in `server.json`, never auth collections, credentials or SQLite metadata. `build-tags.txt` enables exactly the SQLite features tested in `internal/bundle/sqlite_test.go`; do not add icu, userauth, allow_uri_authority, secure_delete, vacuum, foreign_keys, app_armor or os_trace, and keep the reader's denial of `dbstat`, `pragma_*`, `sqlite_schema`, FTS shadow tables and writes.
- Keep the vendored server in `internal/pocketcontext/` under its upstream name. Review security fixes in PocketContext (see `docs/origin.md`) and in the vendored server (`internal/pocketcontext/VENDORED.md`) and port them by hand.
- Never introduce the retired product name that `tests/name_check.py` checks for: not in files, file names, messages, tests or the binary.
- Windows is a supported platform: use `filepath`, `sqliteuri.File` for SQLite URIs, and platform files for locks and process creation. Check with `make windows ZIG=/path/to/zig` and `GOOS=windows` vet through the same Zig compiler (README.md, Build).
- Tests use synthetic data in temporary folders. After changes run `make test` (Go tests with the tags in `build-tags.txt`, the launcher test and the release tests), `python3 tests/name_check.py --binary bin/templatecontext`, `python3 tests/identity_check.py --binary bin/templatecontext` and `python3 tests/e2e.py --binary bin/templatecontext` (`make e2e` runs all three); rebuild `ui/dist` first when the reader changes.
- Never commit `bin/`, `ui/dist`, databases, secrets, real data or machine-specific paths: this repository is public.

## Template

- This repository is the template itself, marked by `template.json` (with `go.mod` naming the template module). New products are made with `prompts/new-product.md`, which copies the template to a sibling folder, renames every identity item, replaces `greetings` and records the template tag and commit in the product's `docs/origin.md`. When you add a new identity item (a file name, environment variable, header, storage key, cache folder or asset name containing `templatecontext`), add it to the table in `prompts/new-product.md`.
- `tests/identity_check.py` (`make identity`, CI and release) is inverted here: it passes when the template identity is present. In a derived product, after `template.json` is deleted, it fails on any `templatecontext`, `TemplateContext`, `TEMPLATECONTEXT`, `pocketcontext-template`, `greeting` or port 8098 left in file names, contents or the binary. `--derived` shows that list here. Keep its needles assembled from parts so it never matches itself, and keep its allowlists exact, each entry with a reason.
- The template never publishes releases: `scripts/release.py` builds and validates tag pushes but skips publishing while `template.json` exists. Tag each template version (`vX.Y.Z`) so products can name it; do not attach binaries.
- Keep the template a working product: every change must keep `make ui build test names identity e2e`, both browser tests and `make windows` passing, and the docs, skill and prompt accurate to the code.
