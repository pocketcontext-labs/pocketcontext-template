TemplateContext 0.4.0 adds an opt-in public mode: an application made from the template can serve its web app on a domain with native HTTPS and offer remote MCP with OAuth. Loopback-only stays the default.

- `serve --headless --domain HOST [--acme-email EMAIL] [--mcp]` runs one service on ports 80 and 443 with an automatic Let's Encrypt certificate, without a reverse proxy. Port 80 serves ACME validation and redirects. `--mcp` and `--acme-email` require `--domain`; `--domain` requires `--headless`, `--headless` requires `--domain`, and `--domain` excludes `--tcp-only`, `--port` and `--ui-dev`. There is no `--tunnel` option.
- `open --public` prints a sign-in link for the public origin of the running service. It never starts a server.
- `server.json` gains `"public": {"collections": ["greetings"]}`, the allowlist of collections the public origin exposes. An unlisted collection is denied, and auth or system collections are refused at startup. Public start also refuses when any entry in `tables` is not listed, because SQL and search read every entry in `tables`. A derived product chooses its collections here without Go changes. `/api/realtime` is public too, with subscriptions limited to listed collections.
- MCP offers exactly five tools driven by `server.json`: `read`, `search`, `schema`, `query` and `write`, with OAuth and browser consent for the project's one account. `read` and `write` return and accept only columns listed in `tables`. There are no shell, filesystem or administration tools.
- The security rule changes from "no public listener" to "public only when explicitly requested". The frozen loopback route table `tests/testdata/public_routes.json` is not widened, and there are no per-requester filters. Hosted mode is not part of the template.
- Public mode starts only if the account password was saved with at least 12 characters, at least 5 of them different. The check runs at startup, and a running public service also refuses to save a weaker password. A password set by an earlier release cannot be judged, so such accounts must run `password` first. Loopback use keeps its 8-character minimum.
- A `--domain` service starts without a loopback TCP port. Local data commands, `open` and `tunnel serve` open it on demand, and it stays on loopback.
- **Upgrade:** the new migration `1810000200_public_password.js` runs the first time 0.4.0 opens a database, and 0.3.0 then refuses that database. Keep a copy of the project from before the upgrade if you may need to go back.
- New manuals: [HTTPS hosting](../https.md) and [MCP](../mcp.md). `prompts/new-product.md` and the agent skill cover public mode; the skill does not enable it unasked.

Certificate issuance uses pocketcontext-core's implementation, which PocketContext Atlas and Crew run. A pre-release build was rehearsed on a real domain under systemd (certificate, restart, crash recovery, browser sign-in, and OAuth and MCP from one real client); certificate renewal and OAuth token refresh have not been exercised, and the systemd unit in the manual is Linux only: macOS and Windows need their native service manager and firewall configured by the operator.
