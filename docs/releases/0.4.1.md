TemplateContext 0.4.1 builds on pocketcontext-core 0.2.2, so products made from the template start on the current core release. Nothing changes for an application made from the template: the same commands, data model, routes and MCP tools.

- **pocketcontext-core 0.2.0 → 0.2.2.** Core no longer decides the OAuth scope, the earlier schemas it refuses, the public body limit, the sign-in email route or the consent page's sign-in text; the template supplies them with the values core used before. Core 0.2.1 and 0.2.2 add opt-in features the template does not use (same-origin frames in the reader; a six-digit sign-in code and a session length for hosted mode, which stays out of scope here).
- `build-tags.txt` is unchanged and still matches core's copy.
- **Upgrade:** no migration and no data format change. A 0.4.0 project opens with 0.4.1, and 0.4.0 still opens a project after 0.4.1 used it.
- `new-product.md` downloads this release's source archive, so a new product no longer has to re-apply the core move by hand.
